# WorkDesk

Single-user Gmail → task dashboard. React + Vite + Tailwind v4 (src/client), Hono API (src/server) that runs both as a Cloudflare Worker (Neon via drizzle neon-http) and locally on Node (PGlite in .data when DATABASE_URL is unset; demo user when GOOGLE_CLIENT_ID is unset). See README.md, and docs/FILES.md for every file and what it does.

## Committed work is settled
- Once a function, feature, behaviour or design decision has been committed, do not delete or change it unless the user specifically asks to revise or change that item. Check `git log` / `git diff` to see what is committed.
- New requests are built alongside existing work, not by reworking it. If a request seems to need a committed item changed or removed (including bug fixes, refactors, renames, or "improvements" noticed in passing), stop and ask the user first, naming the item and the proposed change.
- Approval covers only the item the user named; it does not extend to related code.

## Non-negotiable
- Gmail is read-only except for user-approved changes (2026-10-06): (1) opening an email in the viewer marks that conversation read (`markThreadRead`, removes UNREAD only); (2) the user's own labels (`Label_…` IDs) can be created/renamed/recoloured/deleted and added/removed on a conversation, all through `gmailWrite` and its `WRITE_ROUTES`. System labels (INBOX/TRASH/SPAM/UNREAD/…) must never be passable to the label tools. Never add any other Gmail write (trash/delete emails/archive/send/drafts/filters/batchModify) or broader scopes than `gmail.modify`. `tests/gmail-safety.test.ts` enforces this.
- Dismiss / complete change only WorkDesk's database, and every such action writes an `events` row (audit trail).

## Interaction states (every clickable element)
- Base CSS gives everything clickable a hand pointer, disabled controls a not-allowed pointer, 150ms transitions, and turns motion off for `prefers-reduced-motion`.
- Each control also needs visible states: hover (mouse only; Tailwind `hover:` already skips touch), pressed (`active:scale-[0.97]` for buttons/tabs, `active:scale-90` for icon buttons), selected/current (`aria-selected`, `aria-current`, `aria-expanded:` styles), disabled (`disabled:opacity-50`; use `enabled:hover:` so disabled controls don't react).
- Whole cards/rows are tappable (user request 2026-10-06): mark the row `row-click` and the button that opens the item `row-link` (styles.css stretches its tap area over the row; other controls in the row stay on top with their own action). Used by task rows (Tasks page, To-do card, Due Today), email rows and reminder rows.
- Motion (user request 2026-10-07, "animations and page transitions so the app feels responsive"; the Motion block at the end of `styles.css`): each page slides up and fades in (`.page-in`, keyed on the path in `Shell`; it moves with `top`, not transform, so fixed things inside such as the + button stay put), rows of `main ul.divide-y` lists ease in one after another when they first appear (fill mode `backwards`, never `both`/`forwards`: a kept transform makes each row its own layer and later rows covered ⋮ menus, 2026-10-07), backdrops fade, forms and the email viewer grow in on wider screens (phones keep the slide-up sheets), drop-downs drop in (`menu-in` in `PopPanel`), the Undo bar rises, the + button pops in, the opened tab's icon bounces, a ticked `CheckCircle` pops, and a tapped whole row darkens while pressed. Keep animations short (≤ 300 ms) and off under reduce-motion.
- List rows highlight only while one of their controls is hovered (`has-[:is(button,a):hover]:bg-slate-50/80`), and a title turns blue only when the title itself, which opens the item, is hovered (`group/title`).

## Conventions
- Schema change: edit `src/server/db/schema.ts`, then `npm run db:generate` (commit the SQL in `drizzle/`).
- Neon HTTP driver: no interactive transactions; prefer bulk inserts/upserts. Keep Worker requests well under the subrequest limit (each DB query and Gmail call is one).
- Reminders (user request 2026-10-06; formerly Reports, still stored and served as `reports` / `report_periods` / `/api/reports`): a standard add-reminder form (title, date, optional time, repeat, end repeat, remind me = `leadDays`, priority, notes; no labels, no "responsible"). Each occurrence is a `report_periods` row plus a task titled with the reminder name; an occurrence and its task move together (`setPeriodStatus`; "submitted" = done). New occurrences are only added after the latest existing one, so edits never move or repeat past ones. Old reports were converted by migration 0012 (legacy columns kept). Date maths lives in `src/shared/reminderSchedule.ts`; covered by `tests/reminders.test.ts`.
- Gmail sync fetches each message once: downloaded message IDs live in `gmail_messages`; new messages in stored conversations are fetched singly; read/unread comes from the history log without downloads. First sync covers the last 30 days, continued across runs. Covered by `tests/sync.test.ts`.
- Client data is a hybrid: TanStack Query cache persisted to localStorage (`src/client/queryClient.ts`, 5 min stale time); the database is the source of truth. Any change to the shape of API data must bump `CACHE_VERSION`, or phones restore an old copy and screens crash (2026-10-06: a blank Reminders/Settings page); `ErrorBoundary` (main.tsx) shows "Something went wrong — Reload" and clears the saved copy instead of leaving a blank page. Two smaller safety nets sit inside it (user requests 2026-10-11): `PageErrorBoundary` wraps the page area in App.tsx (inside the `key={pathname}` div, so opening another page clears it; the menu, top bar and tab bar keep working; Try again clears the saved copy) and `PreviewErrorBoundary` wraps each attachment preview (`FileBody` in EmailViewer.tsx, keyed by the file; "Couldn't preview this file", the email stays readable; also catches a preview viewer that can't be downloaded). Every screen and list has a `RefreshButton`. Per-request housekeeping on the server is throttled in `src/server/lib/maintenance.ts`.
- Version shown beside the title (for the first 5 seconds after the app opens, then the connection status, user request 2026-10-07; also in the Settings footer and the status's tap message) is computed from git at build time (`appVersion` in `vite.config.ts`): MAJOR from the latest `vN` tag (1 if none), MINOR = commits since it. Don't hard-code versions; a major update is the user tagging `vN`. The build also writes `dist/version.json`; `src/client/autoUpdate.ts` checks it when the app starts and whenever it returns to the screen (at most once a minute) and reloads once if the server has a newer build (2026-10-06: iPhone home-screen apps kept old versions).
- Task/done labels (`users.taskLabelId/doneLabelId`, `src/server/lib/taskLabels.ts`): Gmail→WorkDesk `applyLabelRules` only creates or completes tasks (never reopens/deletes); WorkDesk→Gmail `reconcileThreadLabels` is best-effort and must never block task actions. Every email in tasks and completed tasks must carry the chosen label in Gmail (user request 2026-10-06), even though the app shows no labels on tasks: `labelTaskEmails` catches up (tasks made before the labels were chosen, failed Gmail calls) in batches after each sync and when the labels are saved. The setting stays in Settings > Mail.
