# WorkDesk

Single-user Gmail → task dashboard. React + Vite + Tailwind v4 (src/client), Hono API (src/server) that runs both as a Cloudflare Worker (Neon via drizzle neon-http) and locally on Node (PGlite in .data when DATABASE_URL is unset; demo user when GOOGLE_CLIENT_ID is unset). See README.md.

## Committed work is settled
- Once a function, feature, behaviour or design decision has been committed, do not delete or change it unless the user specifically asks to revise or change that item. Check `git log` / `git diff` to see what is committed.
- New requests are built alongside existing work, not by reworking it. If a request seems to need a committed item changed or removed (including bug fixes, refactors, renames, or "improvements" noticed in passing), stop and ask the user first, naming the item and the proposed change.
- Approval covers only the item the user named; it does not extend to related code.

## Non-negotiable
- Gmail is read-only except for user-approved changes (2026-10-06): (1) opening an email in the viewer marks that conversation read (`markThreadRead`, removes UNREAD only); (2) the user's own labels (`Label_…` IDs) can be created/renamed/recoloured/deleted and added/removed on a conversation, all through `gmailWrite` and its `WRITE_ROUTES`. System labels (INBOX/TRASH/SPAM/UNREAD/…) must never be passable to the label tools. Never add any other Gmail write (trash/delete emails/archive/send/drafts/filters/batchModify) or broader scopes than `gmail.modify`. `tests/gmail-safety.test.ts` enforces this.
- Dismiss / complete change only WorkDesk's database, and every such action writes an `events` row (audit trail).

- Keep phones compact and information-dense (user feedback 2026-10-06: the enlarged mobile UI showed too little). Visible controls stay small; touch devices get at most a modest bump (`h-8 … pointer-coarse:h-9`). ## Interaction states (every clickable element)
- Base CSS gives everything clickable a hand pointer, disabled controls a not-allowed pointer, 150ms transitions, and turns motion off for `prefers-reduced-motion`.
- Each control also needs visible states: hover (mouse only; Tailwind `hover:` already skips touch), pressed (`active:scale-[0.97]` for buttons/tabs, `active:scale-90` for icon buttons), selected/current (`aria-selected`, `aria-current`, `aria-expanded:` styles), disabled (`disabled:opacity-50`; use `enabled:hover:` so disabled controls don't react).
- Whole cards/rows are tappable (user request 2026-10-06): mark the row `row-click` and the button that opens the item `row-link` (styles.css stretches its tap area over the row; other controls in the row stay on top with their own action). Used by task rows (Tasks page, To-do card, Due Today), email rows and reminder rows.
- Motion (user request 2026-10-07, "animations and page transitions so the app feels responsive"; the Motion block at the end of `styles.css`): each page slides up and fades in (`.page-in`, keyed on the path in `Shell`; it moves with `top`, not transform, so fixed things inside such as the + button stay put), rows of `main ul.divide-y` lists ease in one after another when they first appear, backdrops fade, forms and the email viewer grow in on wider screens (phones keep the slide-up sheets), drop-downs drop in (`menu-in` in `PopPanel`), the Undo bar rises, the + button pops in, the opened tab's icon bounces, a ticked `CheckCircle` pops, and a tapped whole row darkens while pressed. Keep animations short (≤ 300 ms) and off under reduce-motion.
- List rows highlight only while one of their controls is hovered (`has-[:is(button,a):hover]:bg-slate-50/80`), and a title turns blue only when the title itself, which opens the item, is hovered (`group/title`).

## Conventions
- Schema change: edit `src/server/db/schema.ts`, then `npm run db:generate` (commit the SQL in `drizzle/`).
- Neon HTTP driver: no interactive transactions; prefer bulk inserts/upserts. Keep Worker requests well under the subrequest limit (each DB query and Gmail call is one).
- Reminders (user request 2026-10-06; formerly Reports, still stored and served as `reports` / `report_periods` / `/api/reports`): a standard add-reminder form (title, date, optional time, repeat, end repeat, remind me = `leadDays`, priority, notes; no labels, no "responsible"). Each occurrence is a `report_periods` row plus a task titled with the reminder name; an occurrence and its task move together (`setPeriodStatus`; "submitted" = done). New occurrences are only added after the latest existing one, so edits never move or repeat past ones. Old reports were converted by migration 0012 (legacy columns kept). Date maths lives in `src/shared/reminderSchedule.ts`; covered by `tests/reminders.test.ts`.
- Gmail sync fetches each message once: downloaded message IDs live in `gmail_messages`; new messages in stored conversations are fetched singly; read/unread comes from the history log without downloads. First sync covers the last 30 days, continued across runs. Covered by `tests/sync.test.ts`.
- Client data is a hybrid: TanStack Query cache persisted to localStorage (`src/client/queryClient.ts`, 5 min stale time); the database is the source of truth. Any change to the shape of API data must bump `CACHE_VERSION`, or phones restore an old copy and screens crash (2026-10-06: a blank Reminders/Settings page); `ErrorBoundary` (main.tsx) shows "Something went wrong — Reload" and clears the saved copy instead of leaving a blank page. Every screen and list has a `RefreshButton`. Per-request housekeeping on the server is throttled in `src/server/lib/maintenance.ts`.
- Version shown beside the title is computed from git at build time (`appVersion` in `vite.config.ts`): MAJOR from the latest `vN` tag (1 if none), MINOR = commits since it. Don't hard-code versions; a major update is the user tagging `vN`. The build also writes `dist/version.json`; `src/client/autoUpdate.ts` checks it when the app starts and whenever it returns to the screen (at most once a minute) and reloads once if the server has a newer build (2026-10-06: iPhone home-screen apps kept old versions).
- Task/done labels (`users.taskLabelId/doneLabelId`, `src/server/lib/taskLabels.ts`): Gmail→WorkDesk `applyLabelRules` only creates or completes tasks (never reopens/deletes); WorkDesk→Gmail `reconcileThreadLabels` is best-effort and must never block task actions. Every email in tasks and completed tasks must carry the chosen label in Gmail (user request 2026-10-06), even though the app shows no labels on tasks: `labelTaskEmails` catches up (tasks made before the labels were chosen, failed Gmail calls) in batches after each sync and when the labels are saved. The setting stays in Settings > Mail, with tick boxes for more labels whose emails go straight to completed tasks (`users.autoDoneLabelIds`, user request 2026-10-06; they act like the done label for Gmail→WorkDesk, but WorkDesk never adds or removes them in Gmail; the task label can't be ticked). Covered by `tests/task-labels.test.ts`.
- Hidden text (Settings > Mail, user request 2026-10-06): saved snippets (signatures, disclaimers) in `hidden_snippets`, left out of the email reader (with "Show hidden text (n)" under the email) and of shared text, including the WhatsApp caption (Share waits until the list is on the device). The caption is made from the email's HTML cleaned the same way as the reader (2026-10-06: Gmail's plain-text copy, with `*bold*` marks, kept a hidden signature in shares). Matching ignores whitespace, case and plain-text marks (`* _ ~ >`, zero-width characters) (`src/shared/snippets.ts`; HTML across text nodes in `src/client/snippets.ts`), covered by `tests/snippets.test.ts`. The list is downloaded once and kept locally (`useSnippets`, `staleTime: Infinity`, user request 2026-10-06): reading emails never asks the server for it; it refetches only after a change in Settings, a Settings refresh, or when the saved copy expires. Gmail is never changed.
- Snooze was removed from the whole app (user request 2026-10-06): no Snoozed tab, button, swipe action or tag, and the `/threads/*snooze` routes are gone. The `snoozed` state and `snoozed_until` column stay for old data; `wakeSnoozed` returns any email still snoozed to Needs decision with an `email.unsnoozed` History entry. Covered by `tests/bulk-actions.test.ts`.
- Labels are the only way to sort emails (categories were merged into them, user request 2026-10-06; old categories were dropped). Labels belong to emails only (user request 2026-10-06): tasks and reminders show no labels and have no label field or filter (`tasks.labelIds` / `reports.labelIds` and the API fields remain but the app no longer sets or shows them). Email filters are "All labels". Covered by `tests/labels-everywhere.test.ts`.
- Loading states (user request 2026-10-06) look like a mobile app: the logo splash on start-up (`index.html`, and `Splash` while sign-in is checked), shimmering `SkeletonList` rows while a list loads, and `Loading`/`Spinner` (brand-blue spinner) for other waits. Never plain "Loading…" text, and never show an empty-state message before the data has arrived.
- Database paused or down (user request 2026-10-06): the server's `onError` turns database failures into 503 `{ error, code: "database_paused" | "database_error", detail }` (`classifyDbError` in `src/server/lib/dbErrors.ts`; Neon usage-limit messages → paused; plain network errors are not treated as database ones). The query client reports them (`src/client/dbStatus.ts`) and `DatabaseIssueDialog` (App.tsx) explains it, shows the free-plan limits, "Open Neon usage" and Try again; if `/me` itself fails, `DatabaseIssuePage` replaces the app. Covered by `tests/db-errors.test.ts`.
- Fonts: Poppins for English (Google Fonts); Malayalam in Noto Sans Malayalam on every device (user request 2026-10-06), self-hosted at `public/fonts/noto-sans-malayalam.woff2` (OFL licence beside it) with a Malayalam-only `unicode-range`, so it downloads only when Malayalam is on screen. It is second in `--font-sans` and is declared again inside the email and Word preview frames (`MALAYALAM_FONT` in `src/client/fonts.ts`; their CSP allows `font-src 'self'`). Emails that set their own font inline still get the device's Malayalam font for those parts.
- Calendar link (user request 2026-10-07, chosen over Google Tasks/Calendar sync so no new Google permission is needed): Settings > Calendar makes a private link `/api/calendar/<token>.ics` (`users.calendar_token`, migration 0015; Make new link replaces the token, Turn off clears it; each logs a History event) that Apple Calendar (webcal://), Google Calendar or Outlook subscribe to. The feed route is public (before the sign-in middleware; the token is the key) and read-only: open tasks with a due date (timed → 30-minute events in UTC, else all day), not reminder tasks, plus every reminder date from 60 days back to a year ahead from `occurrences` (done dates get ✓). Overdue items show on today (user request 2026-10-07, like the Due Today card): open tasks past their date and reminder dates before today still pending (`report_periods` status pending) become all-day events on today, titled with just the name (no "Overdue:", user request 2026-10-07), with "Overdue – was due …" in the details, keeping their UID so calendars move them day by day. Built by `buildCalendar` in `src/server/lib/ics.ts` (escaping, 75-byte line folding safe for Malayalam); covered by `tests/calendar-feed.test.ts`.
- Calendar dates are `YYYY-MM-DD` strings in `APP_TIMEZONE` (default Asia/Kolkata).
- Before finishing: `npm run typecheck` and `npm test`.
- After every change, end the reply to the user with the new version number (user request 2026-10-06): `v<MAJOR>.<MINOR>` as `appVersion` computes it, e.g. `git rev-list --count HEAD` after pushing when there is no `vN` tag (fetch enough history first; the clone is shallow).
