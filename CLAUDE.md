# WorkDesk

Single-user Gmail → task dashboard. React + Vite + Tailwind v4 (src/client), Hono API (src/server) that runs both as a Cloudflare Worker (Neon via drizzle neon-http) and locally on Node (PGlite in .data when DATABASE_URL is unset; demo user when GOOGLE_CLIENT_ID is unset). See README.md.

## Committed work is settled
- Once a function, feature, behaviour or design decision has been committed, do not delete or change it unless the user specifically asks to revise or change that item. Check `git log` / `git diff` to see what is committed.
- New requests are built alongside existing work, not by reworking it. If a request seems to need a committed item changed or removed (including bug fixes, refactors, renames, or "improvements" noticed in passing), stop and ask the user first, naming the item and the proposed change.
- Approval covers only the item the user named; it does not extend to related code.

## Non-negotiable
- Gmail is read-only except for user-approved changes (2026-10-06): (1) opening an email in the viewer marks that conversation read (`markThreadRead`, removes UNREAD only); (2) the user's own labels (`Label_…` IDs) can be created/renamed/recoloured/deleted and added/removed on a conversation, all through `gmailWrite` and its `WRITE_ROUTES`. System labels (INBOX/TRASH/SPAM/UNREAD/…) must never be passable to the label tools. Never add any other Gmail write (trash/delete emails/archive/send/drafts/filters/batchModify) or broader scopes than `gmail.modify`. `tests/gmail-safety.test.ts` enforces this.
- Dismiss / complete / snooze change only WorkDesk's database, and every such action writes an `events` row (audit trail).

## Touch first (always)
- Every UI change must work well by touch. Tappable controls need a hit area of at least 44×44px: the base CSS in `src/client/styles.css` gives every `button`, `a[href]` and `[role="tab"]` an invisible 44px hit area (opt out with `no-tap`). Rely on that invisible area, not on bigger visuals.
- Keep phones compact and information-dense (user feedback 2026-10-06: the enlarged mobile UI showed too little). Visible controls stay small; touch devices get at most a modest bump (`h-8 … pointer-coarse:h-9`). On phones use tight padding (`px-3`), one-row sideways-scrolling tabs (`no-scrollbar`), short labels, and hide descriptive text (page subtitles) rather than wrapping. Home on phones (user requests 2026-10-06) shows the stats as one row of four and then only the Due Today card: no panel switcher; the card has Today / Overdue / Upcoming tabs (user request 2026-10-06; Reminders has its own bottom-bar tab), each list in priority order. To-do and Pending emails are the Tasks and Emails tabs of the bottom bar; New task is a floating + button; manual refresh there is the top bar's sync button (an agreed exception to "every list has a RefreshButton").
- Phones (under 768px) render everything at 90% (user feedback 2026-10-06, "more information on screen"): `styles.css` sets the root font size to 90% and zooms Lucide icons to 0.9. Write text sizes in rem (`text-[0.8125rem]`, not `text-[13px]`) so they scale; tap areas and 16px form text stay in px on purpose.
- Phones (under 768px), and WorkDesk opened from the home screen on any device (`display-mode: standalone`, e.g. iPad), use an app shell (2026-10-06: "doesn't behave like a mobile app, elements not fixed in position"; "every UI element should act like a mobile app"): html/body never scroll, bounce, drift sideways or pinch-zoom (`.app-shell`/`.app-main` in `styles.css`); `Shell` in `App.tsx` is a full-height column (row on wide screens) where the top bar, rail and tab bar stay put and only `<main>` scrolls (reset to the top on each route change). So `sticky` inside pages is relative to `<main>` (add `app-sticky` so it is `top-0` there), and code must not rely on window scrolling. Pull down at the top of a page to refresh (`PullToRefresh`, same as the sync button). Static text isn't selectable and holding things opens no link/image menu; typed text, email text, notes and sheet cells stay selectable (`select-text`). While typing on a phone the tab bar and + button hide. Pinch-zoom remains in the full-screen attachment viewer. Computers in a browser keep normal page scrolling.
- On phones (under 640px) every pop-up is a sheet from the bottom (user request 2026-10-06): `Modal` forms slide up with a grab handle; drop-downs (`Menu`, snooze, labels, notifications, account) go through `PopPanel`, an action sheet with Cancel; all can be pulled down to close (`usePullToClose` in `components/sheet.ts`, which only reacts to touches on its own dialog). Wider screens keep centred forms and drop-downs. New drop-downs must use `PopPanel`.
- The phone bottom tab bar is standard app size (user request 2026-10-06): `--tabbar-h` (56px) plus the safe-area inset, ~24px icons, 0.8125rem labels, five tabs (Home, Emails, Tasks, Reminders, Calendar; History is opened from the top of Settings on phones, with a back link to Settings; the desktop rail keeps it); an agreed exception to "visible controls stay small". The page uses `viewport-fit=cover`, so anything fixed to a screen edge (bars, floating buttons, full-screen dialogs) must add `env(safe-area-inset-*)`.
- The email viewer on phones (under 640px) is an app-style sheet (user request 2026-10-06): it slides up, has a top bar with the close (chevron-down) button on the left, a grab handle and the label/Gmail buttons on the right, and can be pulled down to close (`usePullToClose` in `EmailViewer.tsx`; the pull starts on the header, or on the email while it is scrolled to the top). Attachments never navigate away (2026-10-06: the home-screen app had no way back): Previews (user request 2026-10-06) cover PDF, images, spreadsheets (.xlsx/.xls/.ods/.csv as a table with sheet tabs, dates dd/mm/yyyy, first 500 rows; `SheetPreview`, SheetJS from `@e965/xlsx`, the npm `xlsx` is outdated), Word .docx (`DocxPreview`, mammoth, sandboxed frame; old .doc is download only) and Google Docs/Sheets/Slides/Drive links found in the email (`src/client/driveLinks.ts`, listed with the attachments, shown with Google's `/preview` page plus a Google button because iPhone Safari keeps the Google sign-in out of frames); the office libraries load only when such a file opens. Open shows the preview in a full-screen `AttachmentViewer` dialog (portal, with Back; its close event must not close the email), and Download uses the share sheet on touch devices, a download link elsewhere (`saveAttachment`). A Share button (top bar on phones, header on wider screens; user request 2026-10-06) opens the system share sheet with the email's attachments as files and its text as the message (WhatsApp caption: bold subject and the message, no From or Date lines, user request 2026-10-06): `useEmailShare` fetches the attachments when the email opens because iOS only opens the sheet straight from the tap (button shows a spinner meanwhile; over 25 MB or no file sharing → text only with attachment names; no share sheet → copies the text).
- Email lists are compact (user request 2026-10-06): rows are three lines (sender and time, subject, then labels/status chips sharing the one-line preview), with tight padding. Rows carry no action buttons (user request 2026-10-06: repeated buttons waste space): every email has a tick box and each list has one `EmailBulkBar` toolbar (Select all, Create task, Snooze, Dismiss, Restore, Gmail for a single email) backed by `/threads/bulk-*`; one ticked email opens the task form, several become tasks at once. Phones still swipe. Lists of to-dos use a tick circle (`CheckCircle`), never a "Done" button per row.
- Task rows show no priority badge (user request 2026-10-06): the Due Today list, the To-do list and the Tasks page (open views) run Urgent → High → Medium → Low with no group headings (user request 2026-10-06: the colour bar is enough; `PriorityGrouped`, `src/client/components/PriorityGroups.tsx`), earliest due first within a priority (so overdue leads), and every task row keeps a colour bar for its priority. Completed lists are not grouped. Priority is changed through Edit.
- The Due Today card (formerly "Today / Command Center", renamed by user request 2026-10-06) is a compact list of links: one row per task or reminder (priority colour bar, title wrapping to at most 3 lines, reminder icon, time or date on the right), no sender, tick circle, chips or menu; tapping opens the task details card (`TaskDetails`, which for email tasks names the email and has Open email). Phones still swipe to complete or edit. On wide screens it is the narrower task panel (Due Today : To-do = 0.8 : 1) with its tabs on one sideways-scrolling row (`Segmented oneRow`), and Pending Emails gets more width (left : right = 2 : 1.4) (user request 2026-10-06). The New task button sits on the To-do Tasks card, not Due Today (user request 2026-10-06); phones keep the floating + button. The Pending Emails card header puts its title and the Pending / All emails switch on one line, View all and refresh after them (wrapping below on narrow laptops) (user request 2026-10-06).
- Leave at least 8px between neighbouring tap targets on touch; never put an action or needed information only behind hover (tooltips are extras); give pressed feedback (base `:active` style); keep form text 16px on touch (base CSS) so iOS doesn't zoom.
- Phones (touch screen under 768px, `useSwipeMode`) act on list rows by swiping, like mobile apps (user request 2026-10-06): wrap rows in `SwipeRow` (`src/client/components/SwipeRow.tsx`). Swipe right = main action (complete task / make task from email / restore), swipe left = the other actions as buttons. In that mode the row's own action buttons (check circle, ⋮ menu, Gmail link, email button bar) are hidden so text gets the full width. Mouse and tablet layouts keep their buttons. Swipe actions that remove a row offer Undo via `showUndo`.
- Layout standards (alignment pass 2026-10-06; keep them): pages are left-aligned (no `mx-auto`) so titles line up with the top bar; `PageHeader` keeps the title left and its buttons right on one line, centred with the title (never wrapping under the subtitle); Home card headers are one line (title left, icon/`sm` buttons right) with secondary links in the tabs row (`TabsRow end`) or the card foot; tabs inside narrow cards use `Segmented oneRow`; list rows use `text-[0.9375rem]` for their main line and `text-xs`/`text-[0.8125rem]` for details; tick controls are round (`CheckCircle`).
- Calendar on phones (under 640px, user request 2026-10-06) is an app-style month view: the month name is the page title with ‹ › (and Today) beside it, single-letter weekdays, compact borderless cells (date centred, up to 3 priority dots; today filled, selected ringed; other months' days are only faded numbers with no dots or marks, tapping one goes to its month, and a last week wholly in next month is dropped), swipe sideways to change month; the selected day's list follows. Wider screens keep the bordered grid with titled chips. Every month also shows active reminders' future dates whose task isn't created yet (user request 2026-10-06): hollow dots on phones, dashed chips on wider screens, and a "Coming up" list for the selected day (computed in the browser from `/api/reports` with `occurrences`; dates with an existing occurrence or task are skipped).
- Check new screens on the phone preset (375px wide, touch emulation) as well as desktop.

## Interaction states (every clickable element)
- Base CSS gives everything clickable a hand pointer, disabled controls a not-allowed pointer, 150ms transitions, and turns motion off for `prefers-reduced-motion`.
- Each control also needs visible states: hover (mouse only; Tailwind `hover:` already skips touch), pressed (`active:scale-[0.97]` for buttons/tabs, `active:scale-90` for icon buttons), selected/current (`aria-selected`, `aria-current`, `aria-expanded:` styles), disabled (`disabled:opacity-50`; use `enabled:hover:` so disabled controls don't react).
- List rows highlight only while one of their controls is hovered (`has-[:is(button,a):hover]:bg-slate-50/80`), and a title turns blue only when the title itself, which opens the item, is hovered (`group/title`).

## Conventions
- Schema change: edit `src/server/db/schema.ts`, then `npm run db:generate` (commit the SQL in `drizzle/`).
- Neon HTTP driver: no interactive transactions; prefer bulk inserts/upserts. Keep Worker requests well under the subrequest limit (each DB query and Gmail call is one).
- Reminders (user request 2026-10-06; formerly Reports, still stored and served as `reports` / `report_periods` / `/api/reports`): a standard add-reminder form (title, date, optional time, repeat, end repeat, remind me = `leadDays`, priority, notes; no labels, no "responsible"). Each occurrence is a `report_periods` row plus a task titled with the reminder name; an occurrence and its task move together (`setPeriodStatus`; "submitted" = done). New occurrences are only added after the latest existing one, so edits never move or repeat past ones. Old reports were converted by migration 0012 (legacy columns kept). Date maths lives in `src/shared/reminderSchedule.ts`; covered by `tests/reminders.test.ts`.
- Gmail sync fetches each message once: downloaded message IDs live in `gmail_messages`; new messages in stored conversations are fetched singly; read/unread comes from the history log without downloads. First sync covers the last 30 days, continued across runs. Covered by `tests/sync.test.ts`.
- Client data is a hybrid: TanStack Query cache persisted to localStorage (`src/client/queryClient.ts`, 5 min stale time); the database is the source of truth. Any change to the shape of API data must bump `CACHE_VERSION`, or phones restore an old copy and screens crash (2026-10-06: a blank Reminders/Settings page); `ErrorBoundary` (main.tsx) shows "Something went wrong — Reload" and clears the saved copy instead of leaving a blank page. Every screen and list has a `RefreshButton`. Per-request housekeeping on the server is throttled in `src/server/lib/maintenance.ts`.
- Version shown beside the title is computed from git at build time (`appVersion` in `vite.config.ts`): MAJOR from the latest `vN` tag (1 if none), MINOR = commits since it. Don't hard-code versions; a major update is the user tagging `vN`. The build also writes `dist/version.json`; `src/client/autoUpdate.ts` checks it when the app starts and whenever it returns to the screen (at most once a minute) and reloads once if the server has a newer build (2026-10-06: iPhone home-screen apps kept old versions).
- Task/done labels (`users.taskLabelId/doneLabelId`, `src/server/lib/taskLabels.ts`): Gmail→WorkDesk `applyLabelRules` only creates or completes tasks (never reopens/deletes); WorkDesk→Gmail `reconcileThreadLabels` is best-effort and must never block task actions. Every email in tasks and completed tasks must carry the chosen label in Gmail (user request 2026-10-06), even though the app shows no labels on tasks: `labelTaskEmails` catches up (tasks made before the labels were chosen, failed Gmail calls) in batches after each sync and when the labels are saved. The setting stays in Settings > Mail, with tick boxes for more labels whose emails go straight to completed tasks (`users.autoDoneLabelIds`, user request 2026-10-06; they act like the done label for Gmail→WorkDesk, but WorkDesk never adds or removes them in Gmail; the task label can't be ticked). Covered by `tests/task-labels.test.ts`.
- Hidden text (Settings > Mail, user request 2026-10-06): saved snippets (signatures, disclaimers) in `hidden_snippets`, left out of the email reader (with "Show hidden text (n)" under the email) and of shared text, including the WhatsApp caption (Share waits until the list is on the device). The caption is made from the email's HTML cleaned the same way as the reader (2026-10-06: Gmail's plain-text copy, with `*bold*` marks, kept a hidden signature in shares). Matching ignores whitespace, case and plain-text marks (`* _ ~ >`, zero-width characters) (`src/shared/snippets.ts`; HTML across text nodes in `src/client/snippets.ts`), covered by `tests/snippets.test.ts`. The list is downloaded once and kept locally (`useSnippets`, `staleTime: Infinity`, user request 2026-10-06): reading emails never asks the server for it; it refetches only after a change in Settings, a Settings refresh, or when the saved copy expires. Gmail is never changed.
- Labels are the only way to sort emails (categories were merged into them, user request 2026-10-06; old categories were dropped). Labels belong to emails only (user request 2026-10-06): tasks and reminders show no labels and have no label field or filter (`tasks.labelIds` / `reports.labelIds` and the API fields remain but the app no longer sets or shows them). Email filters are "All labels". Covered by `tests/labels-everywhere.test.ts`.
- Loading states (user request 2026-10-06) look like a mobile app: the logo splash on start-up (`index.html`, and `Splash` while sign-in is checked), shimmering `SkeletonList` rows while a list loads, and `Loading`/`Spinner` (brand-blue spinner) for other waits. Never plain "Loading…" text, and never show an empty-state message before the data has arrived.
- Calendar dates are `YYYY-MM-DD` strings in `APP_TIMEZONE` (default Asia/Kolkata).
- Before finishing: `npm run typecheck` and `npm test`.
- After every change, end the reply to the user with the new version number (user request 2026-10-06): `v<MAJOR>.<MINOR>` as `appVersion` computes it, e.g. `git rev-list --count HEAD` after pushing when there is no `vN` tag (fetch enough history first; the clone is shallow).
