# WorkDesk

*Every email accounted for. Every task tracked.*

WorkDesk turns a Gmail inbox into a work desk. Every email that asks you to do something becomes a decision, every
decision becomes a task or a record, and nothing gets lost in the inbox.

## Who it's for

WorkDesk is for people **whose work is assigned to them by email**, especially:

- **HR staff in private companies**: joining formalities, leave and salary queries, appraisals, contract renewals,
  exits, statutory returns and requests from managers.
- **The establishment section of a government office**: circulars, orders and letters from higher offices, staff
  service matters (increments, probation, retirement and pension papers), periodic returns and replies with deadlines.

If your day starts with an inbox full of requests, each with its own deadline, and you also look after a list of
employees, WorkDesk is built for you. It is a **personal tool for one person**: only the owner's Google account can
sign in.

## How it works, in three steps

1. **Every new email waits in Pending** until you decide what to do with it.
2. **You decide:** turn it into a **task** (with a due date), **send it to another section/team**, or **remove** it.
3. **Nothing is lost:** tasks stay linked to their email, a new reply on a task's email is flagged, and **History**
   records every decision.

WorkDesk runs in any computer browser and can be installed on a phone's home screen, where it behaves like an app.

## Features

- **Side menu (computers):** labelled buttons in two groups, My work and Office, with Settings always at the
  bottom; shrink it to icons only with the button beside Settings (remembered on that device). It fits any window
  height, scrolling the list when the window is short.

### Home: the day at a glance
- **Counters:** emails waiting for a decision, pending jobs, work due today, upcoming reminders.
- **Due Today:** today's events and tasks with overdue ones first, plus tabs for overdue, upcoming and reminder
  tasks, and staff increments that fall due.
- **To-do:** open tasks, tasks waiting for a reply, and completed tasks. Select several to complete or change them
  together.
- **Pending emails:** the inbox items still waiting for a decision.
- **Tag filter:** a filter icon on the Due Today and To-do cards narrows them to one tag.

### Emails
- **Tabs:** Pending, Other sections, Removed, and All emails, with search, an unread filter and a label filter.
- **Read inside WorkDesk:** the whole conversation, with long address lists folded and repeated signatures or
  disclaimers hidden. Opening an email also marks it read in Gmail. On a computer the Emails page opens it beside
  the list (split view), with the attachment previews under the email.
- **Attachment previews:** PDF, pictures, Excel/CSV, Word, PowerPoint (slide text), and Google Docs/Sheets/Drive
  links in the email. Old Word/PowerPoint formats (.doc, .ppt) explain why they can't be shown and offer Download.
- **One-tap decisions:** Create task, Make event, Remove (or send to another section), Restore. Select many emails
  at once.
- **Share:** send an email and its attachments to another app, such as WhatsApp.
- **Already done:** when a new message arrives in a conversation whose task you completed, the email comes back to
  Pending marked "Already done on <date>", so you can tell a follow-up from new work.
- **Hide senders:** newsletters and other routine senders can skip Pending; they still appear under All emails.

### Tasks
- **The basics:** title, due date and time, priority, notes. Lists are ordered Urgent → High → Medium → Low.
- **Checklist:** break a task into steps and tick them off.
- **Links:** keep the Google Sheet, portal page or Drive file a task needs with it; open them from Task details.
- **Waiting for a reply:** set the date a reply is expected; the task comes back to Due Today on that day or when
  the reply is late.
- **"For":** link a task to an employee, a designation or the whole office.
- **Tags:** your own coloured tags (e.g. *Payroll*, *Audit*, *Recruitment*); filter and search by them.
- **Quick edits:** change the date, time or priority straight from a task's chips.
- **New reply alert:** a task is flagged when its email gets a new message.
- **More than one email:** add other Pending emails to a task or an event from its details; they leave Pending,
  carry the task's labels in Gmail, and a new reply on any of them flags the task.
- **Automatic tasks:** WorkDesk creates tasks for contracts ending, probation declarations and retirement paperwork
  (see Employees).

### Reminders
- **Anything that repeats:** monthly returns, meetings, renewals, bill payments: a date, optional time, repeat
  (daily to yearly), an end date and how many days ahead to remind you.
- **Each date becomes a task** in time; completing either one completes both.
- **Links** to the spreadsheet, document or folder you need, **tags**, and a link to an employee or designation.
- **Pause and resume**, and a details view with past and upcoming dates.

### Events
- **Meetings, trainings and programmes:** date, start and end time, venue or meeting link, who organises it, which
  employees attend, notes and links. Events can repeat like reminders.
- **Your own event types:** Meeting, Training and Programme to start with; add, rename, arrange or remove types in
  Settings. Removing a type keeps its events.
- **Make event from an email:** a meeting notice becomes an event filled from the email; the email leaves Pending
  (a new reply brings it back).
- **Preparation task (optional):** a task a chosen number of days before, which moves with the event.
- **Each date on its own:** mark it done, move it, or cancel it without touching the other dates.
- **Everywhere it matters:** today's events on Home, the calendar, the employee's page, the calendar link, a phone
  notification an hour before, and CSV export/import.

### Calendar
- **Month view** of tasks, reminders and events; tap a day to see its list.
- **Private calendar link:** see everything in Apple Calendar, Google Calendar or Outlook (a read-only copy).

### Employees
- **Staff records:** permanent and temporary employees with ID number, contact details, date of birth, joining
  date, increment date, retirement date, pay and contract details, and day off (Sunday off, the default, or a
  weekly off), grouped by designation (drag to arrange).
- **An employee's own page:** every detail, their open and completed tasks, reminders, saved logins, the events
  they attend and history.
- **Increments:** due increments appear on Home; marking one done asks for the new pay and moves the date a year on.
- **Contracts ending:** a week before a temporary contract ends, a task asks whether to renew or end it.
- **Probation:** when an employee nears the end of probation, a task to declare it or change the date.
- **Leave account:** each permanent employee's page keeps their leave account: the balance of earned leave, half pay
  leave and the other leaves you keep, with every entry (opening balance from the service book, credits,
  adjustments). Settings › Leave lists the leave types with their rules: the Kerala Service Rules leaves (EL, HPL,
  commuted leave, LND, EOL, maternity, miscarriage, hysterectomy, paternity, adoption, special disability and
  hospital leave) are built in with their rule numbers and limits, every figure editable with Reset to KSR, and a
  leave not used can be switched off. It credits a year's leave to everyone at once (for example 20 days of HPL),
  and marks the gazetted posts.
  Employees have Gazetted officer and Probation declared Yes / No in their details.
- **Marking leave:** Mark leave (on the employee's page or the Employees page) takes the days off the balance
  (commuted leave takes double HPL; LND may go below zero), warns when there isn't enough or a KSR limit is crossed
  (180 days of EL at a time, EL + commuted over 240 in one run, LND without a medical certificate, LND while other
  leave is at credit…), notes whether it is on a medical certificate, and makes a task with the
  paperwork steps, different for gazetted officers (application, apply leave, leave CTC, relieving / joining CTC
  form received, joining report in SPARK, joining CTC, AG payslip) and others (application, check leave account, office proceedings, SPARK, attendance, SB update, joining
  report), due the day they are back. Record the rejoining date (an early return gives the days back), change or
  cancel a leave. The **Leave** page lists every leave, newest first, with where it stands (on leave, due back,
  upcoming, rejoined, cancelled), filtered by employee, type or state; choosing an employee shows their leave
  account there. An employee's page has one line with their balances that opens it.
- **Attendance register:** a page that looks like the paper register: a row per person with this year's CL and CH,
  a column per day of the month. Tap a day's number to select everyone and mark them present in one go, or pick
  cells (a person's month, a range) and mark Off, CL, half-day CL or Absent. Holidays (set in Settings ›
  Attendance, with second Saturdays) and Sundays are shaded, and leave marked on the Leave page fills its days by
  itself. Phones show one day at a time. **CH**: work on a holiday earns a compensation leave; Mark CH asks which
  holiday each one is for and only offers holidays worked in the last 3 months, with each post's yearly limit
  (G.O. 43/2021). **Weekly-off staff**: 6 days of work earn an off, and an off can only be marked once earned; offs due (or the days of duty still needed for one) show by the name, and more than 12 days
  in a row is flagged (and warned about before marking). Starting figures carry over a year already under way,
  entered in Settings or imported from a spreadsheet. Tap anyone's CL / CH cell for their figures; CH that must be
  taken within a week are listed above the register. The register stretches to fit the screen. The Summary button opens a summary of the month for each person; Print gives
  an A4 page with signature lines, and Download a spreadsheet of the month. Home reminds you from 11 am when people
  aren't marked yet today; `/markattendance` is a plain page for phones to mark one person's CL, CH or off for a
  day or a range, and each employee's page shows their month so far.
- **Yearly leave credits:** switch a leave to automatic in Settings › Leave and it is credited on each employee's
  service anniversary: HPL 20 days a year, earned leave as 1/11 of the days on duty (less leave taken) for staff
  whose probation is declared. Opening balances can be imported from a spreadsheet (Import / Export › Leave balances).
- **EOL and surrender:** marking extraordinary leave offers to move the next increment and the probation declaration
  date by its days (with Undo); Surrender (in a leave account's Entry) takes earned leave off the balance and makes a
  task with the surrender steps. Assistants can read a leave account and mark leave.
- **Retirement:** a list of everyone retiring within 12 months, and a retirement/pension paperwork task with a
  checklist.
- **Joining and relieving:** Join or Relieve someone (on their page or the Employees page) and WorkDesk makes a task
  with the steps: joining report, adding in SPARK, letter to the institution, service book received; or relieving
  order, relieve in SPARK, letter from the institution, update service book, send LPC / service book. A table on the
  Employees page shows every person's steps as Pending, Waiting or Done; change them there or in the task, and the
  task completes itself when every step is done. Staff already working here whose joining papers aren't complete
  can be added from Settings › Employees, ticking the steps already done; the same goes for relieving, including
  someone already marked as left or not yet in WorkDesk.

### File register
- **Every file of the section:** paper files and e-files, listed by file number then subject. Search, filter by
  status or by tags (the same tags as tasks and reminders), and tap a number to copy it.

### Registers
- **Pending updates to registers:** add your registers (service book register, stock register…) in Settings; then
  note each update a register needs and the staff member who has to sign it or give the information.
- **One place for all of them:** the Registers page lists every pending entry (unassigned ones under General),
  filtered by person or register,
  beside a card per register with its own list (type an entry and press Enter to record it there) and the date it
  is updated until; its Updated button marks it updated until today and clears the done entries.
- **A task only when you want one:** give an entry a due date and it becomes a task in To-do and Due Today;
  ticking either one ticks both. Done entries are kept behind "Show done".

### Logins
- **Saved logins for work websites:** for example each employee's login to a payroll or HR portal, or a shared
  login used by a role (such as the drawing officer or the section clerk). One website can have many logins.
- **Safe by design:** passwords are stored encrypted, stay hidden until you tap Show or Copy, hide again after 30
  seconds, and every Show or Copy is recorded in History.

### Search and History
- **Search** across emails and tasks: titles, notes, subjects, senders and tag names.
- **History** (in Settings): a record of every decision and change (emails decided, tasks completed, labels
  changed, passwords shown…). Removed emails can be restored from here.

### Gmail labels and sections
- **Labels:** create, rename, recolour and delete your Gmail labels, and add or remove them on an email.
- **Task and done labels:** emails that are tasks (or done) get a chosen label in Gmail, and labelling an email in
  Gmail makes it a task (or completes it) in WorkDesk.
- **Sections:** each of your other labels stands for another section or team; an email carrying one moves to
  "Other sections".

### Notifications
- **Bell:** overdue tasks, tasks due today and new replies.
- **Phone notifications** (home-screen app): a morning summary at a time you choose, a note when a task is due, a
  note an hour before an event, and a count on the app icon.

### Import and Export (in Settings)
- **Full backup** of everything WorkDesk keeps, and a restore that only adds what is missing.
- **Spreadsheet (CSV) import and export**, with sample files, for the file register, employees, tasks,
  reminders, events and leave balances.

### Settings
- **General:** light, dark or automatic appearance; phone notifications; the Gmail connection; office details
  (letterhead, seat, signature, file number pattern, usual recipients, office codes) used for drafting letters.
- **Mail:** hidden senders, hidden text (signatures, disclaimers), task/done labels, sections, Gmail labels.
- **Employees:** which employee you are (your row and page get a "You" tag), designations and types of temporary
  employees.
- **Leave:** leave types and their rules, Credit now, gazetted posts.
- **Events:** the types of events (Meeting, Training, Programme…).
- **Registers:** the registers you keep (add, rename, arrange, remove).
- **Tags:** rename, recolour, delete and arrange tags.
- **Calendar:** the private calendar link.
- **Assistant:** connect ChatGPT or Gemini (see below); **Assistant help** lists every command with what to ask.
- **History** and **Import / Export** (see above).
- **Queue:** the background work (Gmail sync, phone notifications, Gmail task labels, upkeep): what is waiting,
  running, paused or failed, what each run did, with Run now and Retry. Work that doesn't fit in one run waits for
  the next one and failures are tried again, so nothing is lost.
  A change of yours that fails (for example when the database or Gmail is busy) is saved there and done again
  automatically, or waits for your check if part of it had already been saved. The **Calls log** lists every call
  each request made to the database, Gmail and the notification services (never your data), with failed ones kept
  for 30 days.

### Assistant (ChatGPT, Gemini)
- **Ask an AI assistant about your work:** "what is overdue?", "summarise the PDF in the HMIS email", "who retires
  this year?". WorkDesk is an MCP server: add its address (Settings › Assistant) in ChatGPT or Gemini and approve the
  connection on WorkDesk's own page.
- **Reads everything:** emails and attachments (PDF, Excel, Word, PowerPoint, pictures), tasks, reminders, events,
  employees, registers, the file register, History and settings, with names and plain words rather than codes. Saved
  website passwords are never shared.
- **Everyday changes, when you allow them:** switch on Allow changes and the assistant can create, change and
  complete tasks, make tasks from emails, remove emails or send them to a section, add emails to a task, record and
  tick register entries, add events or mark their dates, add or change reminders (also pause them and mark dates
  done), and add or change file register entries — asking you before each one. It can never delete
  anything, at most 10 items at a time and a limit of changes an hour that you set.
- **Staff actions, with a switch of their own:** Allow staff actions lets it join and relieve employees and set their
  steps, mark increments done with the new basic pay, renew or end contracts, declare probation, mark registers
  updated, and add or change employee details.
- **Ready-made prompts:** Morning briefing, Reply to this email (an official letter draft in English or Malayalam,
  using your office details — WorkDesk never sends mail), Employee status, Monthly work diary, Pending email triage
  (proposes what to do with each Pending email and applies what you approve), Month-end returns check, Weekly
  review and Staff matters this month. Just ask for one; ChatGPT and Gemini fetch
  them as a tool, and assistants with a prompts menu list them there too.
- **You stay in control:** every request an assistant makes is listed in the assistant log (kept apart from History,
  exportable as CSV), each change is also in History marked "via ChatGPT", the bell shows changes you haven't looked
  at yet, and Disconnect stops it at once.

### Phone app
- **Install it on your phone's home screen.** Swipe a row to act on it (with Undo), pull down to refresh, and
  pop-ups open as bottom sheets.
- **Offline viewing** of what you last loaded, and automatic updates when a new version is deployed.
- **Any language:** text in other scripts (for example Malayalam) displays correctly, including in previews.
- **Safety nets:** if one page or one attachment preview fails, only that part shows a message; the rest keeps
  working.

## Privacy and what WorkDesk does to Gmail

- **Gmail is changed in only two ways:** opening an email marks it read, and your own labels can be managed and
  added to or removed from emails. System labels (Inbox, Trash, Spam, Unread…) can't be touched. The code has **no
  way to delete, trash, archive or send email**, and an automatic test (`tests/gmail-safety.test.ts`) fails if such
  code is ever added. Removing an email, completing a task, tags and imports change only WorkDesk.
- **What is stored:** for each email only the subject, sender, Gmail's short snippet, dates and IDs; message bodies
  are never stored. Gmail access tokens, the notification key and saved website passwords are encrypted. Passwords
  are never included in lists, offline copies, exports or anything an assistant can read.
- **Tags vs labels:** Gmail labels belong to emails (and mark sections). Tags belong to WorkDesk's tasks and
  reminders and never reach Gmail.

## Run it locally

You need [Node.js](https://nodejs.org) 24 or later.

```bash
npm install
```

```bash
npm run dev
```

Open http://localhost:5173. No accounts are needed to try it. With no `.env` file, WorkDesk:
- keeps its database in `./.data` (PGlite, a built-in Postgres), and
- signs you in as a demo user with sample emails and reminders. In demo mode, **Simulate new email** stands in for
  checking Gmail.

To start again with fresh demo data, stop the server and delete `.data`.

| Command | What it does |
|---|---|
| `npm run dev` | API on :8787 plus the app on :5173 |
| `npm test` | Automatic checks, including the Gmail safety check |
| `npm run typecheck` | TypeScript check |
| `npm run db:generate` | Create a migration after changing `src/server/db/schema.ts` |
| `npm run db:migrate` | Apply migrations to Neon (if `DATABASE_URL` is set) or to the local database |
| `npm run deploy` | Build the app and deploy it to Cloudflare |

## Use it with your own Gmail

### 1. Google Cloud sign-in
1. In https://console.cloud.google.com, create a project (for example "WorkDesk").
2. Under **APIs & Services → Library**, enable the **Gmail API**.
3. Under **Google Auth Platform → Branding / Audience**, set up the consent screen. For a Google Workspace mailbox
   choose **Internal**; for an ordinary @gmail.com account choose **External** and add yourself as a test user.
4. Under **Data access**, add the scope `.../auth/gmail.modify` (reading, marking read, and labels).
5. Under **Clients**, create a **Web application** client with these redirect URIs:
   - `http://localhost:5173/api/auth/google/callback`
   - `https://<your-worker>.workers.dev/api/auth/google/callback` (add this once it's deployed)

> While an *External* app is in **Testing**, Google expires its sign-in after 7 days, so you sign in again weekly.
> Internal (Workspace) apps don't have this limit. Check Google's rules for restricted scopes before publishing an
> External app: https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification

### 2. Settings file (`.env`)
Copy `.env.example` to `.env`, then fill in `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `OWNER_EMAIL` (the only
Gmail address allowed to sign in), and two random secrets. Make each secret with:

```bash
node -e "console.log(crypto.randomBytes(32).toString('base64'))"
```

Use one for `SESSION_SECRET` and another for `TOKEN_ENC_KEY` (this key encrypts tokens and saved passwords; keep it
safe and don't change it later). Restart `npm run dev` and sign in.

### 3. Database (Neon)
Create a free project at https://neon.tech, put its connection string in `DATABASE_URL`, and run
`npm run db:migrate`.

### 4. Put it online (Cloudflare Workers)
```bash
npx wrangler login
```
```bash
npx wrangler secret put DATABASE_URL
```
Repeat the second command for `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `OWNER_EMAIL`, `SESSION_SECRET`,
`TOKEN_ENC_KEY` and `APP_URL` (your `https://….workers.dev` address). Then:
```bash
npm run deploy
```
One Worker serves both the app and its API. A timer runs the background queue every 10 minutes (due phone
notifications, Gmail, labels, upkeep). On the free plan a run may make 50 calls (`SUBREQUEST_LIMIT` in
`wrangler.jsonc`); on the Paid plan raise it (e.g. 1000) so each run does more.
Phone notifications need no extra setup.

### 5. Automatic deploys from GitHub (optional)
`.github/workflows/deploy.yml` deploys every push to `master`: it runs the checks (a failure stops the deploy),
updates the database, builds the app and publishes it. Add three secrets under the repository's **Settings → Secrets
and variables → Actions**:

| Secret | Value |
|---|---|
| `CLOUDFLARE_API_TOKEN` | From https://dash.cloudflare.com/profile/api-tokens, using the **Edit Cloudflare Workers** template |
| `CLOUDFLARE_ACCOUNT_ID` | Your Cloudflare account ID (`npx wrangler whoami` shows it) |
| `DATABASE_URL` | Your Neon connection string |

## How it's built

React + Vite + Tailwind (the app), Hono (the API) on Cloudflare Workers, Neon Postgres with Drizzle, and the Gmail API.

```
src/
  client/   The app: pages/ (one file per screen), components/ (shared parts), api.ts (calls to the server)
  server/   The API: app.ts (sign-in, routes), routes/ (endpoints), lib/ (Gmail, sync, reminders, notifications…),
            db/schema.ts (tables), worker.ts (Cloudflare + timer), dev.ts (local)
  shared/   Rules and types used by both sides
  sw/       Service worker: offline copy and phone notifications
drizzle/    Database migrations, applied in order
tests/      Automatic checks (npm test)
```

Every file and what it does is listed in **[docs/FILES.md](docs/FILES.md)**. The rules for changing the code are in
**[CLAUDE.md](CLAUDE.md)**.

**How emails move:** *Pending* (needs a decision) → *task*, *Other sections*, or *Removed*.
- A new message in a removed email, or in one handled by another section, brings it back to Pending.
- A new message on an open task flags the task "New reply"; after the task is completed it returns to Pending.

**Light on Gmail and the database:** the first check covers the last 30 days; after that only Gmail's change log is
read, and each message is downloaded once. The browser keeps a copy of loaded screens, so pages open instantly and
work offline; every screen can be refreshed on demand.

## Version number

The version (e.g. **v1.150**) shows briefly next to "WorkDesk" after the app opens, at the bottom of Settings and
on the sign-in page. It is worked out from git when the app is built:

- **The second number** goes up by one with every commit.
- **The first number** changes only for a major release. Mark one with a tag before deploying; the count restarts:
  ```bash
  git tag v2
  ```
